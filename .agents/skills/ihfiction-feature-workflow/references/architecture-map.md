# Repository architecture map

Use this map for orientation, then inspect the nearest relevant files. Prefer targeted searches over reading whole directories.

## Runtime and ownership

| Concern | Primary location | Notes |
|---|---|---|
| Orchestration | `src/aspire/IHFiction.AppHost/` | Starts API (`fiction`), web (`web`), PostgreSQL, MongoDB, Redis, Keycloak, and migration (`migrations`) resources. |
| Schema application | `src/aspire/IHFiction.MigrationService/` | Applies EF migrations. It is explicit-start in Development; non-development API startup waits for completion. |
| Minimal API slices | `src/IHFiction.FictionApi/Features/<Purpose>/` | A slice commonly combines request/response models, use-case logic, errors, and nested endpoint mapping. |
| API infrastructure | `src/IHFiction.FictionApi/Infrastructure/`, `Extensions/`, `Common/` | Endpoint discovery, response mapping, validation, pagination, links, authorization, and exception handling. |
| Relational domain and mappings | `src/lib/IHFiction.Data/<Area>/Domain/` and `Configurations/` | PostgreSQL via `FictionDbContext`; migrations live under `Migrations/`. |
| Document bodies | MongoDB driver usages in API/data code | Story/work content uses `IMongoCollection<T>` in existing slices. Follow its nearest analogue rather than EF abstractions. |
| Shared contracts/utilities | `src/lib/IHFiction.SharedKernel/` | Cross-layer primitives, validation, links, filtering, sorting, shaping, and notification contracts. |
| Shared Blazor UI | `src/lib/IHFiction.SharedWeb/` | Feature pages, components, services, and assets under `Features/<Purpose>/`; reusable UI, theme, metadata, and generated client stay shared. |
| Web host | `src/IHFiction.WebClient/` | Interactive Server host, authentication handler, and app composition. |
| API contract generation | `src/IHFiction.FictionApi/openapi.json` | Generated by a normal host-runtime API build. |
| Typed client generation | `src/lib/IHFiction.SourceGenerators/` and `IHFiction.SharedWeb.csproj` | NSwag-based source generator consumes the OpenAPI file; preserve the documented build graph workaround and force the local package refresh after generator changes. |
| Tests | `tests/IHFiction.UnitTests/`, `tests/IHFiction.IntegrationTests/` | Unit behavior plus Testcontainers-backed PostgreSQL/MongoDB boundaries. Browser tests may be added using the installed Blazor Playwright skill. |

## Find the nearest analogue

Read `docs/FEATURE_LAYOUT.md`, choose the user purpose, then search for the operation. Resources do not define feature boundaries:

```powershell
rg -n "<FeatureNoun>|<Operation>" src tests --glob '*.cs' --glob '*.razor'
rg --files src/IHFiction.FictionApi tests | rg '<Purpose>|<Analogue>'
```

Then inspect one complete slice across layers. Useful anchors:

- ordinary author endpoint: `Features/Discovery/GetAuthor.cs`
- authenticated author mutation: `Features/Authoring/CreateStory.cs`
- hybrid PostgreSQL/MongoDB content: `Features/Authoring/UpdateStoryContent.cs`
- queued fan-out: `Features/Authoring/PublishStory.cs` plus `Features/Following/NotificationFanoutHandler.cs`
- shared UI page/service: `SharedWeb/Features/Discovery/StoryDetail.razor` plus `SharedWeb/Features/Discovery/StoryDiscoveryService.cs`
- private author workspace reads: `SharedWeb/Features/Authoring/AuthorWorkspaceService.cs`
- agent protocol endpoint: `Features/AgentAccess/ConfirmAgentIdentityClaim.cs`; shared protocol conventions stay in `AgentAuthProtocol.cs`
- sitemap generation and tests: `SharedWeb/Features/Discovery/DynamicSitemapNodeProvider.cs` and the matching Discovery test folder
- unit and integration naming: matching folders under both test projects

Search architecture mechanisms directly when needed:

```powershell
rg -n "RequireAuthorization|AuthorizationService" src/IHFiction.FictionApi
rg -n "IMessageBus|PublishAsync|Handle\(" src/IHFiction.FictionApi
rg -n "IMongoCollection|FictionDbContext" src/IHFiction.FictionApi src/lib/IHFiction.Data
rg -n "SocialPreviewMetadata|StructuredDataMetadata|SectionContent" src/lib/IHFiction.SharedWeb
```

Read `ARCHITECTURE.md` for intentional API and Wolverine decisions. Read `.agents/WORKAROUNDS.md` before changing unusual build or package plumbing.
